# 工程化建议

## MVP 边界

先证明一条稳定链路：把研究假设和实验变量配置化，运行基线与对照实验，统一计算指标，生成可追溯报告。暂不接入外部 LLM、分布式训练和在线服务，避免环境、费用和结果波动影响第一版验证。

## 关键设计

1. **任务与执行解耦**：JSON 描述假设、数据、基线和实验变体；训练器只负责执行。
2. **结果可追溯**：固定随机种子，保存配置 SHA-256、完整参数、指标和耗时。
3. **失败可定位**：配置先校验；每个实验独立记录；报告明确最优方案和对比结果。
4. **替换点清晰**：后续替换 `model.py` 即可接入真实论文实现，不影响 runner、报告和测试。
5. **最小验证集**：测试配置校验、同一配置重复运行结果一致、产物存在且指标达到基本门槛。

## 从 MVP 扩展到真实 AutoResearch

- 增加论文元数据、数据集版本和 commit ID。
- 增加 ablation、早停、预算限制和失败重试。
- 接入 PyTorch / Hugging Face，并记录 GPU、依赖锁定和 checkpoint。
- 增加 MLflow 或 SQLite 作为实验索引。
- 最后再接入 LLM Agent，让 Agent 生成候选改动；所有改动仍经过测试、指标门槛和人工审核。
