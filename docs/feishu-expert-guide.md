# 飞书项目申请要求整理

> 来源：[`RL env collection · 专家须知`](https://wcngz2jid6iw.feishu.cn/docx/DNPFdZDJWo6K8sx4N9JcvKdPnLh)  
> 整理日期：2026-09-24  
> 说明：本文是申请准备清单，不替代原文；提交前应以原文最新要求为准。

## 仓库准入重点

- 使用 GitHub 私有仓库，仓库从未公开过。
- 最近一次提交应在要求的时间窗口内。
- 代码规模、提交数量和 milestone 数量须以真实 Git 历史为准；文档不同段落对 milestone 数量有 5/6 的表述，按 6 个准备更稳妥。
- 仓库应是真实持续维护的工程，不能为申请临时新造，也不能把课程作业或整段复制的开源项目作为本人项目。
- 起始状态应能离线构建和运行。
- 提交私有仓库链接并授予审核方只读权限。

## Milestone 记录

每个阶段应有连续的真实 commit 区间，并说明：

1. 起止完整 commit SHA；
2. 目标与背景；
3. 实现要点；
4. 对外可观察的行为变化；
5. 如何验证；
6. 与前后阶段的依赖关系。

最好能展示起始提交验证失败、结束提交验证通过。还应准备至少 5 条真实的后续 TODO。

## 过程材料

审核关注完整过程，而不是只有 commit message。建议保留问题定义、现状痛点、方案比较、最终设计、参数和接口、测试验收、影响范围、排期以及对应 commit 区间。

## 合规检查

提交前清理个人敏感信息、密钥、令牌、证书、数据库凭据、客户数据、内部地址、非公开技术成果和第三方商业秘密。不得补造提交历史、虚构 milestone 备注或提交本人未参与开发的仓库。

## 当前项目的适用范围

AutoResearch Lite 目前适合作为论文复现和工程能力作品集。它尚未声称满足上述代码文件数量、提交数量和连续 milestone 的正式准入要求；若用于正式申请，应选择已有真实开发历史的工程，或从现在开始按真实迭代积累记录。
